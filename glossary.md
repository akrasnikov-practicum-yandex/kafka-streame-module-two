## Абстракции потока

- **KStream** — поток **событий**: каждая запись самостоятельна и ничего не отменяет.
  Две записи с одним ключом — два независимых факта («alice отправила сообщение»,
  «alice отправила ещё одно»).
- **KTable** — поток **состояний**: запись с ключом `K` заменяет предыдущее значение
  этого ключа. Это таблица «последнее известное значение на ключ», построенная из
  лога изменений. Две записи с одним ключом — старое значение и новое.
- **GlobalKTable** — KTable, которую каждый экземпляр приложения держит **целиком**,
  по всем партициям исходного топика. Обычная KTable делится между экземплярами так
  же, как партиции между консьюмерами группы.
- **Дуальность потока и таблицы** (stream-table duality) — ключевая идея Kafka Streams:
  таблица это свёртка потока изменений, а поток это лог изменений таблицы. Одни и те
  же данные читаются и так, и так — в работе топик `blocked_users` читается как поток
  команд, а сворачивается в таблицу списков.

## Состояние

- **State store** — локальное хранилище ключ-значение, в котором оператор держит своё
  состояние (счётчики, накопленные списки). Живёт рядом с приложением, а не в брокере.
- **Persistent state store** — state store на диске, поверх **RocksDB**. Переживает
  перезапуск приложения, в отличие от in-memory-хранилища. Требование задания —
  именно persistent.
- **RocksDB** — встраиваемое key-value-хранилище на LSM-дереве, стандартный движок
  persistent state store в Kafka Streams. В .NET-ветке используется тот же движок:
  Streamiz тянет его нативной зависимостью.
- **Changelog-топик** — служебный compacted-топик, куда Kafka Streams дублирует каждое
  изменение state store. Именно он делает локальное состояние отказоустойчивым:
  при перезапуске на другом узле store восстанавливается проигрыванием changelog.
  Создаётся автоматически, имя вида `<app-id>-<store>-changelog`.
- **Global store** — state store, который целиком реплицируется на каждый экземпляр
  приложения (`addGlobalStore`). Процессоры получают к нему read-only доступ
  автоматически, подключать его к процессору не нужно и нельзя.
- **Interactive Queries** — чтение state store снаружи топологии, напрямую из
  приложения (например, чтобы отдать состояние по HTTP).

## Топология

- **Топология** (topology) — граф обработки: источники (топики), операторы и стоки.
  Описывается декларативно, а Kafka Streams превращает описание в физический план
  выполнения.
- **DSL** — высокоуровневый API (`stream`, `filter`, `join`, `aggregate`). Покрывает
  большинство задач и читается как цепочка преобразований.
- **Processor API** — низкоуровневый API: свой класс процессора с прямым доступом
  к state store и контексту. Нужен там, где DSL не выражает логику — например, когда
  на одну входящую запись требуется много обращений к хранилищу.
- **`processValues`** — DSL-операция, отдающая запись в процессор Processor API без
  права менять ключ. Заменила устаревший с Kafka Streams 3.3 `transformValues` (KIP-820).
- **`application.id`** — идентификатор приложения Kafka Streams. Одновременно и
  `group.id` консьюмер-группы, и префикс имён служебных топиков и каталогов состояния.
  Два приложения с одним `application.id` считаются экземплярами одного приложения
  и делят между собой партиции.
- **Task** — единица параллелизма: одна задача обслуживает один набор партиций
  и владеет своей копией state store. Задачи распределяются между экземплярами
  приложения и потоками внутри них.

## Операции

- **Stateless-операции** — не нуждаются в памяти о прошлом: `filter`, `map`,
  `mapValues`, `branch`.
- **Stateful-операции** — опираются на state store: `aggregate`, `count`, `reduce`,
  join'ы, оконные операции.
- **`aggregate`** — свёртка записей с одним ключом в накопленное значение через
  функцию-аккумулятор. В работе так строится список заблокированных: поток команд
  `block`/`unblock` сворачивается в множество идентификаторов.
- **KStream-KTable join** — обогащение события текущим состоянием таблицы. Срабатывает
  **только на записи потока**: обновление таблицы само по себе ничего не выдаёт наружу.
- **`leftJoin`** — join, который вызывает функцию-объединитель даже если в таблице
  ничего не нашлось (тогда второй аргумент `null`). Стандартный приём фильтрации
  «по отсутствию в таблице»: вернуть `null` и отсеять следующим `filter`.
- **Tombstone** — запись со значением `null`. В compacted-топике означает удаление
  ключа, а в KTable — удаление строки. В работе так снимается слово из списка
  запрещённых.

## Партиционирование

- **Co-partitioning** — условие, при котором join выполним локально: у обоих входов
  одинаковое число партиций и одинаковая схема ключей, поэтому связанные записи
  всегда попадают в одну задачу. Нарушение условия Kafka Streams исправляет сама,
  вставляя repartition-топик.
- **Repartition-топик** — служебный топик, через который Kafka Streams перекладывает
  поток с новым ключом, когда операция этого требует. Стоит одной дополнительной
  записи и чтения, поэтому ключи в работе подобраны так, чтобы он не понадобился.
- **Compacted-топик** (`cleanup.policy=compact`) — топик, в котором Kafka хранит
  **последнее** значение каждого ключа, а старые версии со временем удаляет. Основа
  для KTable-справочников: сколько бы обновлений ни было, полный актуальный список
  восстанавливается чтением топика с начала.

## ksqlDB

- **ksqlDB** — надстройка над Kafka Streams с SQL-подобным языком: те же потоки,
  таблицы и агрегации, но запросами, без компиляции приложения.
- **STREAM** — то же, что KStream: неизменяемая последовательность событий.
- **TABLE** — то же, что KTable: текущее состояние по ключу.
- **Push query** (`EMIT CHANGES`) — подписка: запрос не завершается и выдаёт
  результат по мере поступления новых данных.
- **Pull query** — точечный запрос текущего значения из материализованной таблицы,
  как обычный `SELECT` в базе. Завершается сразу.
- **`COUNT_DISTINCT`** — агрегат подсчёта уникальных значений; в работе им считается
  число уникальных получателей.
